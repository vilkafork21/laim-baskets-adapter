# Архитектура и правила исполнения

## Разделение ответственности

`main.py` разрешает пути входных портов и возвращает выходы платформе.
`context.py` читает документы и книгу, сопоставляет роли документов и задаёт
идентичность. `pipeline.py` управляет этапами и публикацией. `contract.py`
собирает только внешний контракт, не вычисляет метрику повторно.

`llm/tasks.py` отвечает за предложения и repair, `llm/prompts.py` — контекст,
`llm/schemas.py` — схемы. Разметка проверяется в `resolve.py`; построчный
план — в `metric/resolve.py`. `metric/engine.py` считает Decimal-оценки,
`metric/baseline.py` проверяет и выбирает официальное значение.

## L: структура

Модель задаёт лист, шапку, физические колонки и способ группировки. Код
определяет границы данных, проверяет совместимость ролей и строит канон.
Предложение модели не мутируется при проверке.

`grouping=column` объединяет строки по идентификатору с продолжением пустых
ячеек. `merged_rows` использует **конкретную колонку-якорь**, а не объединения
во всех колонках. Для старых планов без якоря допустим семантический источник
`session_id`/`input_query`, если именно он объединён. Декоративный merge в
категории или комментарии не меняет число диалогов.

При смешанном оформлении идентификатора (часть продолжений объединена,
часть просто пуста) следует задавать `column`, если это подтверждено методикой.
Объединённая оценка, пересекающая несколько независимых групп, отклоняется;
она не размножается на несколько наблюдений.

Структурный справочник с заголовками «Параметр / Значение» не становится
запросами. Само название листа «Описание» не запрещено: на нём могут быть
настоящие запросы и ответы. Это проверка типовых форм, не универсальное
доказательство семантической правильности разметки.

Запасной лист допускается только после отказа L, если лист не закреплён.
Меньшинство неразбираемых строк может быть отброшено после repair с записью
номеров в `dropped_rows`; потеря большинства или всего канона — `spec_error`.
После L выбранный лист не меняется.

## S: единица, шкала, метод

Необязательный **внутренний** `assessment_mode` задаёт единицу из методики:
`qa`, `turn_with_history`, `dialogue`. Это не новая настройка и не новый порт.
При его отсутствии сохранено прежнее определение по форме данных. Явный
`dialogue` требует групп; score и вес должны быть постоянны внутри группы.
Один повторённый итоговый score и один вес считаются один раз за диалог.

| Метод | Требуемые роли |
|---|---|
| `identity` | Один `final_score` |
| `accuracy` | Один `prediction` и один `target`, совместимые labels |
| `mean_criteria`, `all_criteria` | Не менее двух `criterion` |
| `majority`, `all_assessors` | Не менее двух `assessor_vote` |

Метод и набор источников исполняются как предложены либо отклоняются.
Нельзя молча удалить неудобную колонку или заменить метод. Готовая итоговая
колонка не имеет безусловного приоритета над методикой в отчёте.

`ratio`: голые числа 0..1; `percent`: 0..100; `raw`: иная числовая шкала.
Значение `1` при `percent` означает 1%, даже если все значения не больше 1.
`90%` нормализуется один раз. Отрицательные/слишком большие значения ratio
отправляют план на repair, а не меняют шкалу остальных строк.

Необязательный внутренний `missing_values` явно перечисляет нечисловые
маркеры пропуска по колонкам, например результат формулы вместо оценки.
Числа через него исключать нельзя; основание — в `quotes`, событие —
`declared_missing_values`. Внешний контракт не расширяется: он получает уже
нормализованные numeric-колонки с null и существующий `missing_policy`.

Текстовая оценка требует явного `value_map`; она не исчезает как пропуск при
`numeric`. Инвентарь показывает полный частотный домен коротких категорий
до 64 уникальных значений, иначе `unique_values_complete=false`.

`missing_policy` управляет пустыми оценками. Для `accuracy` отсутствие label
считается пропуском, а не автоматически отдельным классом. Семантику
«оба продукта отсутствуют — это верный ответ» нельзя придумывать по baseline.

Редьюсеры v2 — `mean` и `frequency_weighted_mean`. Вес должен быть физическим,
положительным целым. Глобальный F1, сумма произвольных критериев или другая
неподдерживаемая формула не подменяются средним ради статуса `computed`.

Построчные Excel-формулы со статическими ссылками только своей строки могут
дать score через сохранённый кеш. Межстрочные, внешние, динамические,
именованные и недетерминированные ссылки отклоняются. Формулы не вычисляются;
свежесть кеша не доказана. `formula_score_cached` сообщает об использовании
кеша. Если кеш отсутствует, выбирайте исходные оценки по методике либо
пересчитайте и сохраните книгу вне ноды.

## K: официальная КМ

Вход: только отчёт валидации с `pNNN`, имена листов и подсказка имени из S.
Ни scores, ни пересчитанное число в K не передаются. Длинный отчёт разбивается
на части с исходной нумерацией; его хвост не теряется. L/S сохраняют лимит
контекста документа с предупреждением. Ошибка любой части K не выдаёт
частично извлечённый отчёт за полностью проверенный.

Ответ: массив упоминаний с `metric_name`, `raw`, `paragraph`, `kind`,
`slice_label`, `is_key_metric`, необязательным `comparator`. Виды — `value`,
`slice_value`, `threshold`, `ci_bound`, `other`. Модель не выбирает статус.

Код проверяет число дословно в **указанном** абзаце, включая знак, проценты и
границы токена. Цифры внутри другого числа не являются цитатой. Отклонённые
упоминания остаются в `rejected`.

Выбор: подходящий листу срез, иначе общее значение; далее признак ключевой
метрики и совпадение имени S. Первое число выбирается только для одной
метрики в строке таблицы, а не в произвольном абзаце. Разные метрики не
сливаются потому, что их значения равны. Противоречивые значения дают
`ambiguous_baseline`, отсутствие проверенного итога — `official_baseline_missing`.

Пороги и границы ДИ не становятся baseline. Конфликт порогов даёт
`threshold_ambiguous` без подмены однозначного значения КМ. Проценты переводятся
явно: `0.9%` — это `0.009`, не `0.9`. Без S число без `%` имеет неподтверждённую
шкалу `raw`. Соседний абзац не используется вместо указанного.

## Результаты и ограничения

Успех L/S/K даёт `computed`. Отказ S сохраняет UMR без `main_metric` и
`score_plan_failed`; K всё равно выполняется. Отказ K сохраняет оценки S.
Нечитаемые обязательные входы, невалидный CI или несобранный канон остаются
ошибками, а не «успешной пустой корзиной».

Официальная КМ — из отчёта, `recomputed_value` — отдельный расчёт. Повторного
оценивания строк при присоединении baseline нет. По v2 расхождение
информационное; добавляется `reconciliation_mismatch`. Неполное покрытие
оценками даёт `score_coverage_partial`. Эти предупреждения требуют разбора
до допуска, даже при `computed`.

Клиент повторяет транспортные ошибки и увеличивает бюджет усечённого ответа,
в том числе частичного JSON с `finish_reason=length`. Локальная валидация
JSON обязательна независимо от поддержки structured output шлюзом.

XML-ридер сохраняет порядок блоков DOCX, строки таблиц, вложенные таблицы и
заголовки. Он не распознаёт числа, существующие только на картинке/скане.
UMR публикуется в утверждённом формате; строки не исполняются как формулы.
Размеры XLSX, содержимое файлов, корректность методики и реальные ответы
модели всё равно должны проверяться на корпусе и на платформе.
