# Приёмка на корпусе

## Что считать успешным

Разделяйте четыре результата: файл прочитан; канон корректен; официальная КМ
извлечена с правильной семантикой; расчёт соответствует методике и знаменателю.
`computed` не доказывает все четыре. Сравнивайте единицу оценки, число исходных
и опубликованных наблюдений, исключения, веса, шкалу, цитату и пересчёт.

Единица отчётности — агент + версия + лист + выбранная метрика, а не файл.
Дубликаты, альтернативные выгрузки и разные метрики одного агента не
увеличивают число независимых агентов. Синтетические и реальные случаи
показываются отдельно. Отсутствующие документы не заменяются пустышками.

## Воспроизведение проверенного плана

```bash
python tools/run_corpus.py --manifest /private/reviewed-manifest.json \
  --root /private/artifacts --out /private/reviewed --mode reviewed
```

`reviewed` не вызывает LLM. Он подставляет заранее проверенные предложения
L/S/K и запускает настоящий код чтения, валидации, расчёта и публикации.
Это регрессия реализации, **не результат Sonnet/Haiku/GigaChat**. Исправление
плана аудитором тоже нельзя выдавать за автоматическое восстановление модели.

Каждый случай содержит четыре пути входов, закреплённый лист, `agent_ci`,
`reviewed_proposals` и необязательный `expected`. Поддерживаются ожидания
статуса, значений, числа единиц и режима. Все планы, номера цитат, SHA-256 и
исключения должны быть доступны для независимой проверки.

## Живой шлюз

Адрес и ключ задаются окружением; секреты не записываются в манифест.

```bash
export LAIM_LLM_URL='https://YOUR-AUTHORIZED-GATEWAY/api/v1/chat/completions'
export AI_GATEWAY_API_KEY='YOUR_KEY'
python tools/run_corpus.py --manifest /private/reviewed-manifest.json \
  --root /private/artifacts --out /private/live-gigachat \
  --mode live --model gigachat-3-ultra
```

`live` **не читает `reviewed_proposals`**, но сравнивает результаты с `expected`.
Используется существующий OpenAI-совместимый клиент ноды. Это не адаптер
Anthropic Messages API и не замена `claude -p`. Для сравнения с прежними
прогонами Claude нужен тот же авторизованный runner и зафиксированная модель.

Для проверки автоматического выбора листа нужен отдельный манифест с пустым
`sheet_name`. Корпус с вручную закреплёнными листами не измеряет это умение.
Нужно отдельно проверить неоднозначные multi-agent книги, где выбор
оператора действительно обязателен.

## Протокол и гейт

`results.json` содержит статус каждого случая, код/причину отказа, режим,
официальное значение и пересчёт, покрытие, исключения, предупреждения и хэши
четырёх входов. Рядом лежат журнал и XLSX. Любой runtime exception или
несовпадение явного `expected` делает код выхода runner ненулевым.

Неполные входы и ожидаемый отказ неподдерживаемого метода — отдельные исходы,
не успех автоматизации. Для релизного гейта проверяйте число таких исходов,
не только код выхода. Проверенные числовые ожидания следует получать
независимо от движка, а не копировать из текущего `computed`.

Production-приёмка требует живого прогона полного корпуса и целевой платформы,
разбора всех расхождений и неполного покрытия, проверки семантики пустых
классов, нескольких ключевых метрик и воспроизводимости версий артефактов.
Обещание корректности на произвольных будущих агентах из одного корпуса не
следует. Новые формы следует добавлять как регрессии без per-agent ветвлений
в runtime и без ослабления проверок ради доли `computed`.

Результаты содержат клиентские данные. Не публикуйте их в открытом GitHub;
не включайте сырые LLM-запросы/ответы и корпус в общедоступные CI-artifacts.

## Инвентаризация и независимая арифметика

```bash
python tools/audit_inputs.py --root /private/artifacts --out /private/artifact-audit.json
python tools/verify_arithmetic.py --manifest /private/reviewed-manifest.json \
  --root /private/artifacts --results /private/reviewed/results.json \
  --out /private/independent-arithmetic.json
```

Parquet-инвентаризация требует `pyarrow` только на стенде проверки; это не
runtime-зависимость ноды. Pickle проверяется статически, без загрузки объектов.
Контрольная арифметика читает Excel отдельно от движка и проверяет явно заданные
планы. Она не подтверждает семантический выбор метрики и не является общим
интерпретатором всех форм Excel. Для нового формата сначала добавьте независимый
контроль единиц, пропусков и знаменателя.
