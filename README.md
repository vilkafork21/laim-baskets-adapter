# LAIM baskets adapter

Преобразует корзину и три документа в эталонный UMR, план оценки и официальную
ключевую метрику (КМ). Модель предлагает трактовку; код проверяет ссылки,
группы, шкалу, цитаты и вычисляет результат. Значение из отчёта не подгоняется
под пересчёт корзины.

**`computed` означает, что вычислительный путь завершён, а не что агент
допущен к production.** Проверяйте сверку baseline, полноту оценок и методику.

## Входы, выходы, настройки

| Вход, обязательный | Формат |
|---|---|
| `test_set` | XLSX или XLSM; макросы и формулы не исполняются |
| `validation_report` | DOCX; единственный источник официальной КМ |
| `development_report` | DOCX; описание данных и метода |
| `assessor_instruction` | DOCX или UTF-8 TXT; правила разметки |

Выходы: `reference_umr` (DataFrame), `monitoring_metric` (контракт КМ),
`km_result` (журнал), `umr_artifact` (путь к XLSX).

Настройки: `model_id=glm-5.2`, `sheet_name=""`, `agent_ci=""`.
`sheet_name` закрепляет лист. `agent_ci`, например `CI09000001`, задаёт
идентичность вместо имени временного каталога. Новых портов нет.

Контракты сохранены: `laim-monitoring-metric.v2`, `laim-umr.v2`,
`laim-run-report.v1`. Ветка не включает миграцию `research-dev` на v3.

## Путь исполнения

```text
main.py: порты и настройки
  context.py: проверка четырёх файлов, чтение, идентичность
  pipeline.py:
    L — структура → канон
    S — методика → оценки единиц и пересчёт
    K — отчёт → проверенные кандидаты и официальный baseline
  contract.py: контракт v2
  export/umr.py: XLSX без исполнения строк как формул
```

S и K деградируют независимо; после успешного L корзина сохраняется.
Ошибка S/K не переключает лист на «Описание». Подробные правила, шкалы и
диагностика: [архитектура](docs/architecture.md).

## Проверка и сборка

Python 3.12, база платформы `py312-simple`. Runtime-зависимости перечислены
в `requirements.txt`; инструменты проверки не входят в зависимости ноды.

```bash
python -m pip install -r requirements.txt pytest 'ruff==0.15.5'
ruff check .
ruff format --check .
python -m pytest -q
```

ZIP для импорта содержит `descriptor.json` в корне и все файлы из
`sourceFiles`. `tools/`, тесты и данные корпуса в runtime не включаются.

## Проверка на артефактах

[Порядок приёмки](docs/acceptance.md) отделяет реальный вызов модели от
воспроизведения заранее проверенного плана. Манифест с привязкой файлов,
отчёты и данные хранятся **вне публичного репозитория**.

```bash
python tools/run_corpus.py --manifest /private/reviewed-manifest.json \
  --root /private/artifacts --out /private/replay --mode reviewed
```

Этот запуск проверяет исполнение плана и расчёт, **не качество автоматического
извлечения LLM**. Ни число прошедших unit-тестов, ни доля `computed` не заменяют
приёмку на живой модели и разбор расхождений.
