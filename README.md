# LAIM baskets adapter

Нода подключения версии агента. Превращает первичную корзину и документы в воспроизводимый план расчёта и **кандидат**, который должен быть проверен перед мониторингом.

## Путь данных

1. XLSX + отчёт валидации + отчёт разработки + инструкция → предложение структуры и методики.
2. Код проверяет ссылки на колонки, нормализацию, единицу оценки, формулу и пересчитывает baseline.
3. Выходы: `reference_umr`, кандидат `monitoring_metric` v3, журнал `km_result`, Excel `umr_artifact`.
4. Проверяющий подтверждает точный `definition_id` через `laim-kriteria-selector`. Без подтверждения регулярная оценка недоступна.

`assessment_mode` выбирается по методике: `qa`, `turn_with_history`, `dialogue`. Наличие объединённых ячеек, групп или повторённых оценок само по себе не выбирает единицу. Два диалога с итогами 1 и 0 дают 0.5 при любой корректной упаковке; три отдельных ответа 1, 1, 0 дают 2/3.

Нормализация источника явная: `numeric`, `percent`, `label` или таблица значений. Добавление строки не меняет шкалу остальных строк. `evaluation.score_values` — полный дискретный домен итоговой оценки, а не только границы. Для среднего критериев необходимо перечислить допустимые промежуточные значения.

## Проверка и исправление при подключении

`run_context` задаёт `agent_ci` и `solution_version`. Без версии кандидат нельзя подтвердить.

В `km_result.decisions.onboarding_plan` публикуются исходные предложения `layout` и `metric`. Их можно проверить, исправить и передать в необязательный вход `onboarding_plan`. Повторная компиляция такого плана не вызывает LLM и применяет те же схемы и проверки. Ручной план закрепляет выбранный лист; ошибку нельзя исправить автоматическим переходом на другой лист.

`evaluation` содержит рубрику, `score_values`, направление качества, границу дефекта, обязательные свидетельства, наблюдаемое prediction и профиль извлечения трейсов. Для FIPA требуется `external_party` из протокола агента. Изменение определения, версии или SHA-256 артефактов меняет `definition_id`; прежнее подтверждение теряет силу.

`reference_umr` несёт `dataset_role=reference` и `definition_id`. При исправлении плана публикуется новая корзина с новым идентификатором. Подтверждённое определение и соответствующую корзину платформа должна сохранять вместе и подавать в регулярные прогоны.

## Ограничения допуска

Официальное значение берётся из отчёта валидации. Расхождение с пересчётом не исправляется подгонкой формулы или заменой официального значения: selector оставляет baseline недопущенным. Неполная рубрика, отсутствие версии и неподдерживаемая шкала также требуют исправления при подключении.

LLM предлагает трактовку и не гарантирует её правильность. Проверка человеком относится к содержанию определения; SHA-256 фиксирует его идентичность и не является электронной подписью проверяющего.

## Запуск и проверка

Самодостаточная Sber DS-нода Python 3.12: `descriptor.json`, `main.py`, `measurement.py`, `laim_basket/`, `requirements.txt`.

```bash
python3 -m pytest -q
ruff check .
```

v3 несовместим с прежним операционным контрактом v2. Переключать нужно согласованный комплект producer/selector/converter/assessor/tests/aggregator из `research-dev`; смешанный комплект не допускается.
